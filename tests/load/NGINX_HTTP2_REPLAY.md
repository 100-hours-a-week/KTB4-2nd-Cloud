# 실제 생성 API의 HTTP/2 부하 재현

10/27 강사 시험에서 서버에 도달한 `POST /api/trips`는 133,875건이었다. 모두 HTTP/2였고, 141개 연결을 재사용했다. 첫·마지막 완료 시각은 10:08:16.556~10:13:14.882 KST다. 관측 평균은 448.75 HTTP/s, 완전한 1초 구간의 중앙값은 481건, 최대는 564건이었다.

이 수치는 서버의 HTTP 완료 기록이다. 발생기 송신률, 실패한 연결, 원래 본문·인증 주체·동시 Stream 수는 복구할 수 없다. 이번 시험은 확인된 조건에 접근하며, 모르는 조건까지 동일하게 재현했다고 표현하지 않는다.

## 입력과 실행 조건

`fixtures/nginx-instructor-20261027-profile.json`에 실제 299개 1초 bucket과 원본 접근 로그 SHA를 보존한다. 실행 전 길이·순서·합계·최대값을 검사한다. 서버의 완료 분포를 이번 클라이언트의 요청 시작 스케줄로 사용하는 근사이며, 최초·마지막 bucket은 부분초다.

기존 발생기의 k6 v2.3.0으로 실제 생성 API를 호출한다. HTTP/2 협상을 응답마다 확인하고 Keepalive를 재사용한다. 새 합성 계정 3개 중 1개의 Access Token·CSRF를 부하에 사용한다. 별도 정상 조회 계정 11007과 실제 사용자 계정은 부하에 사용하지 않는다.

JWT 서명키는 App에 남긴다. 합성 세션만 두 SSM 암호화 터널로 App에서 발생기에 전달하며, Mac은 메모리로 중계한다. 토큰을 출력하거나 Mac 파일에 저장하지 않는다. 발생기 세션 파일은 `/run`의 0700 디렉터리·0600 파일로 둔다.

본문은 고유한 여행명 10자, 2025-01-01~03, 지역 코드 50110으로 고정한다. DB에 실제 여행을 생성하되 사진 업로드나 AI 후속 작업을 추가하지 않는다. 원래 본문과 정확히 같다는 주장은 하지 않는다. 시작 이벤트·요청 ID·201의 tripId를 기록하며 불확실한 POST를 재시도하지 않는다. 생성한 시험 데이터는 감사용으로 보존한다.

각 k6 VU는 한 번에 요청 1개만 진행한다. 원래 동시 Stream 수를 모르므로 이 선택을 명시한다. **VU 수는 TCP 연결 수가 아니다.** 실제 연결 수·HTTP/2·재사용 여부는 요청 ID를 통해 Nginx의 connection·worker_pid와 대조한다. 초마다 배정 시작점을 회전해 전체 요청 수의 클라이언트 간 차이를 1건 이내로 유지한다. 일부 연결에만 요청이 편중돼 불필요한 재연결을 만드는 것을 피한다.

## 단계와 보호

| 단계 | 클라이언트 | 본부하 | 목적 |
| --- | ---: | --- | --- |
| smoke1 | 1 | 1초·1RPS | 인증·본문·HTTP/2·201 확인 |
| small16 | 16 | 30초·64RPS | 짧은 재사용 부하 |
| medium64 | 64 | 30초·256RPS | 확대 전 확인 |
| instructor141 | 141 | 299초·원본 초별 133,875요청 | 관측 연결 수와 요청 분포에 접근 |
| instructor128 | 128 | 같은 원본 요청 분포 | 연결 한도와 HTTP 요청량을 분리 |

준비 연결은 초당 20개 시도로 연다. 원래 SYN 속도를 모르므로 원래 초기 burst와 같다고 하지 않는다. 연결 141개를 만들려고 기존 TCP 보호 128·신규 SYN 20/s burst40을 풀지 않는다. 실제 성립 수가 목표보다 작으면 그대로 기록한다. 128개 변형은 원본과 연결 수가 다른 별도 시험이다.

컨트롤러는 앞 단계가 실패하면 자동 확대하지 않는다. 실패 자료를 확인한 뒤 필요한 단계만 새 출력 폴더에서 `--stages`로 선택한다. k6 maxDuration, systemd RuntimeMaxSec(본부하+45초)·메모리 768MiB·CPU 150%로 실행을 제한한다.

프로토콜 불일치·예상 밖 응답·스케줄 누락은 결과 실패로 남긴다. 실패 클라이언트는 해당 POST를 재시도하지 않고 종료하므로 뒤의 실제 송신량도 줄 수 있다. 누락 Counter가 0이어도, 중도 종료한 클라이언트의 미시작 요청을 별도로 계산해야 한다.

App의 호스트·프로세스 CPU/FD·TCP·ENA·접근/오류 로그를 1초마다 수집한다. 별도 합성 계정의 인증 조회를 지속하고, Mac에서도 `--http-version 2`로 로그인 HTML과 BE 헬스를 새 TCP/TLS 연결로 조회한다. 실제 협상 버전이 2인지도 검사한다. 화면 렌더링·OAuth·LTE를 검증한 것은 아니다.

독립 외부 probe가 실패하거나 정체되면 진행 부하를 중단한다. 호스트 자원·내부 정상 조회·ENA는 단계 전후 가드이므로 모든 자원 초과를 즉시 감지한다고 표현하지 않는다.

## 실행과 증거 보존

실행 위치는 Cloud 저장소다. `run-nginx-h2-stage.py`는 기존 발생기 root·대상·k6 버전·합성 세션 유효 시간을 검사한다. 파일 경로는 고정하고, 환경변수는 화이트리스트로 구성해 외부의 HTTP 디버그·프록시·프로토콜 강제 설정이 섞이지 않게 한다.

```bash
python3 tests/load/scripts/run-nginx-h2-trials.py \
  --context /private/tmp/yeodam-h2-442/context.json \
  --external /private/tmp/yeodam-h2-442/external \
  --output /private/tmp/yeodam-h2-442/trials --execute
```

context는 기존 #438 형식에 sessionId를 추가한다. capture·normal·external에는 새 UUID를 쓴다. 단계별 실제 source.js·source-lib.mjs와 SHA를 보존한다. 코드 보완으로 중단한 준비 실행은 삭제하거나 최종 성공 표본에 합치지 않는다.

종료 후 자기 합성 계정의 세션·CSRF만 폐기하고 발생기 세션 파일을 삭제한다. 계정·여행·지역 행은 유지한다. DB와 클라이언트 started·response·201 ID를 대조해 중복·미응답 커밋·201 누락을 확인한다.

`fetch-nginx-rehearsal.py --include-h2-generator`는 화이트리스트에 있는 #442 이벤트·결과·소스·프로필만 내보낸다. 세션 풀은 제외한다. App/Loki ID 다중집합·파일 SHA·수집 오류를 대조하고 원본과 한국어 그래프를 로컬 작업 기록에 연결한다. 429 발생량만으로 사용자 보호 성공을 판정하지 않는다.
